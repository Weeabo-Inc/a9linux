# transforms applied to source-n69.dtb for QEMU mode=fill
GRAFT: added pl011@9000000 (arm,pl011, QEMU virt's UART) + 24MHz fixed clock. QEMU emulates this UART; A9's apple,s5l-uart at 0x20A0C000 is NOT emulated.
EDIT: /aliases/serial0 now points at the grafted pl011 (was /soc/serial@20a0c0000). /chosen/stdout-path stays "serial0", so the kernel's alias->node resolution is still exercised.
FILL: /memory@800000000/reg  <0x08 0x00 0x00 0x00>  ->  QEMU RAM base=0x40000000 size=0x40000000. On the phone the loader must fill this with the REAL DRAM map (HANDOFF §8.11); QEMU RAM lives at 0x40000000 and A9 DRAM at 0x800000000, so this substitution is a QEMU necessity, not a proposed value.
FILL: /cpus/*/cpu-release-addr cpu@0 <0x00 0x00> -> 0x40002000; cpu@1 <0x00 0x00> -> 0x40002000. On the phone this must be the address iBoot/the loader actually parks the secondary core on (HANDOFF §8.11); the value here is a QEMU RAM address and is NOT a claim about A9. EVERY cpu node needs it -- filling only cpu@0 leaves cpu@1 writing its entry address to PA 0.
dtc emitted 81 warning line(s) on recompile (clocks_property x7, gpios_property x5, phys_property x1, power_domains_property x66, resets_property x1, simple_bus_reg x1); full text in n69-qemu-fill.dtb.dtc-warnings.txt. These are all pre-existing upstream shape warnings (phandle-less clock/power-domain cells after decompile) plus the upstream /soc/bus@20c000000 unit-address/reg mismatch.
