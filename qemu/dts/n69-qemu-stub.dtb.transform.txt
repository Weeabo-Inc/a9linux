# transforms applied to source-n69.dtb for QEMU mode=virt
GRAFT: added pl011@9000000 (arm,pl011, QEMU virt's UART) + 24MHz fixed clock. QEMU emulates this UART; A9's apple,s5l-uart at 0x20A0C000 is NOT emulated.
EDIT: /aliases/serial0 now points at the grafted pl011 (was /soc/serial@20a0c0000). /chosen/stdout-path stays "serial0", so the kernel's alias->node resolution is still exercised.
FILL: /memory@800000000/reg  <0x08 0x00 0x00 0x00>  ->  QEMU RAM base=0x40000000 size=0x40000000. On the phone the loader must fill this with the REAL DRAM map (HANDOFF §8.11); QEMU RAM lives at 0x40000000 and A9 DRAM at 0x800000000, so this substitution is a QEMU necessity, not a proposed value.
FILL: /cpus/*/cpu-release-addr cpu@0 <0x00 0x00> -> 0x44004000; cpu@1 <0x00 0x00> -> 0x44004000. On the phone this must be the address iBoot/the loader actually parks the secondary core on (HANDOFF §8.11); the value here is a QEMU RAM address and is NOT a claim about A9. EVERY cpu node needs it -- filling only cpu@0 leaves cpu@1 writing its entry address to PA 0.
SUBSTITUTE: added arm,cortex-a15-gic at 0x08000000/0x08010000 (QEMU virt). Our DTB's controller is apple,s8000-aic at 0x20E100000 -- a completely different irqchip that QEMU cannot emulate. ALL interrupt behaviour in these runs is QEMU's GIC, not A9's AIC.
SUBSTITUTE: /timer interrupts <0x01 0x02 0x04 0x01 0x03 0x04> (AIC FIQ numbering) -> GIC PPI numbering. The A9 has no EL2, which is why upstream only lists phys+virt; QEMU's GIC gives us all four.
DISABLE: 14 A9 nodes set status="disabled" (any MMIO read from an unmapped QEMU address is a guest data abort, which would oops the probe): clock-ref, performance-controller@202220000, serial@20a0c0000, i2c@20a110000, bus@20c000000, power-management@20e000000, interrupt-controller@20e100000, backlight@20e200080, pinctrl@20f100000, pinctrl@2100f0000, power-management@210200000, watchdog@2102b0000 ...
EDIT: removed operating-points-v2/performance-domains from cpu nodes (providers are A9 PMGR blocks QEMU does not have).
FILL: /chosen/framebuffer@7c000000 reg=0x7c000000+0x300000 640x1136 stride=2560 format=a8r8g8b8 status=okay (dropped power-domains = <0x19 0x28>: Apple PMGR is not emulated, and a provider that never probes would leave simpledrm deferred forever)
ADD: /reserved-memory/framebuffer@7c000000 (no-map) so the allocator cannot hand the scanout buffer to anything else. On the phone this region must be excluded from the DRAM the kernel is told about.
SET: /chosen/bootargs = "console=ttyAMA0 earlycon=pl011,0x9000000 rdinit=/init panic=-1 loglevel=7 mailbox=0x44004000". On arm64 there is no command-line register -- the DT is the only channel, so a loader that forgets this boots with an EMPTY command line (no console=, no rdinit=).
SET: /chosen/linux,initrd-start/end = 0x44200000..0x442e5c06. Property names matter: the kernel reads only the linux,initrd-* forms; a bare initrd-start is ignored and the boot dies later at 'VFS: Cannot open root device'.
dtc emitted 79 warning line(s) on recompile (clocks_property x7, gpios_property x5, phys_property x1, power_domains_property x64, resets_property x1, simple_bus_reg x1); full text in n69-qemu-stub.dtb.dtc-warnings.txt. These are all pre-existing upstream shape warnings (phandle-less clock/power-domain cells after decompile) plus the upstream /soc/bus@20c000000 unit-address/reg mismatch.
